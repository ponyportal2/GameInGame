# Blender assets in GameSmith

Use the GameSmith `blender` tool (your harness adds its normal tool prefix). No shell, Blender UI or Blender MCP server is needed.

1. Write a reusable workspace-relative `.py` file using your ordinary write/edit tool. It runs with `bpy`, the workspace as cwd, and `GAMESMITH_WORKSPACE` set. Use absolute output paths derived from `Path.cwd()`. Keep inputs, exports and previews inside the game workspace. Python is executable code, not a filesystem sandbox.
2. `blender(action="start", script="art/build.py", render="art/preview.png")` waits for the player's **Run script / Cancel** decision. Each run requires approval unless the player enabled **Automatically approve Blender scripts** in Settings. That separate setting defaults off and is independent of reload auto-approval. The player sees the path, full UTF-8 source (up to 256 KiB) and SHA-256. Approval runs a private snapshot; changes to the original before launch or to the snapshot are rejected. Imported modules and other files are not frozen. Do not try to approve through tool arguments or bypass a rejection. After approval the background job returns a `run_id`. Optional `blend="art/source.blend"` opens an existing scene before running the script. To inspect an existing blend, omit `script`; embedded auto-run scripts remain disabled and this does not request Python approval. `render` is optional; if supplied, your scene must have a camera, lights and sensible render settings.
3. Poll `blender(action="status", run_id=...)` until `completed`, `failed` or `cancelled`. Default status is compact: exit status, a short `log_tail`, mesh totals, world bounds and up to 64 existing GLB/blend/PNG artifacts in `art/` and the render directory (not necessarily generated by this run). To debug, request `status` with `details=true`; `offset` and `limit` paginate object details, at most 64 per call. Follow `report.next_offset` until -1. The retained report covers at most 256 objects; `objects_truncated` indicates omitted objects. Details include parent, local/world location, dimensions and materials. Failed runs keep a larger log tail; detailed logs remain bounded to the last 32 KiB. A failed job is yours to fix. `stop` cancels the process tree; the chat Stop button also cancels Blender work. Do not start another job until the previous one has exited.
4. `blender(action="inspect", path="art/preview.png")` returns the PNG as image content plus dimensions. This requires a vision-capable selected model and harness image support. If vision is unavailable, use the scene report and explain that visual appearance was not verified. Do not claim to have viewed JSON/base64 as an image. Previews must be PNG, at most 8 MiB, 4096 per dimension and 4 megapixels. Prefer 512–1024 px.
5. Improve the asset from the render/report, rerun and inspect. Save editable source with `bpy.ops.wm.save_as_mainfile(filepath=str(Path.cwd()/"art/source.blend"))`. Export game models with `bpy.ops.export_scene.gltf(filepath=str(Path.cwd()/"art/model.glb"), export_format='GLB')`. Prefer modest mesh/material counts and embedded GLB textures. Never depend on Godot importing `.blend` or on an editor-generated `.import` cache.
6. GameSmith runs generated games without Godot's editor import pipeline. Do not use `preload("model.glb")`, `res://art/...`, hardcoded user directories or script `resource_path` to locate game assets. Before the generated root enters the tree, the host attaches a workspace-aware helper in its `gamesmith_assets` metadata. In `main.gd`'s `_ready()`:

```gdscript
var assets = get_meta("gamesmith_assets")
var model = assets.load_glb("art/model.glb") # GLTFDocument/GLTFState, no editor import
if model != null:
    model.name = "GardenModel"
    add_child(model)
```

For helper nodes, find the ancestor carrying that metadata; this also works from nested scripts:

```gdscript
var game = self
while game != null and not game.has_meta("gamesmith_assets"):
    game = game.get_parent()
if game == null:
    push_error("Missing GameSmith asset helper")
    return
var assets = game.get_meta("gamesmith_assets")
var model = assets.load_glb("art/model.glb")
if model != null:
    add_child(model)
```

`assets.path("art/sprite.png")` returns the absolute current-workspace path for `Image.load_from_file`, `FileAccess`, or manual `GLTFDocument` loading. It survives reload, separate tests, and supported game rename. It accepts relative paths only and is a convenience API, not a GDScript sandbox. For sprites use `ImageTexture.create_from_image(image)`. Never invent an editor-generated `.import` or `.tscn` dependency.

7. Verify integration, not only export. First run a successful **headless** test. Then, for visual changes, start a `rendered` test if the player has enabled rendered testing, and request `test_game_action(action="screenshot")`. Poll its action ID to receive the actual Godot image. Inspect framing, scale, orientation, materials, lighting and animation there: the Blender preview alone does not prove the imported scene looks right. Use `inspect` on the test root, then copy returned `path` values exactly, preserving `@`. Set `depth=2` (maximum 4, total 100 nodes) for a bounded hierarchy; assign stable node names in generated code. Stop the test and request reload before handoff. If rendered testing or vision is unavailable, state that the in-game appearance was not visually verified; do not bypass the player's setting.

## Iterate on a saved scene

For non-trivial assets, establish the major forms and composition first, render a cheap preview and inspect it before investing in detail. Preview again after significant visual changes.

First save the guide's `example_script` as `art/build.py` and run `blender(action="start", script="art/build.py", render="art/preview.png")`. It builds the scene, saves `art/source.blend` and exports `art/model.glb`; the optional tool render then writes the preview. Poll until completion and inspect the PNG.

For subsequent adjustments, write `art/tweak.py` instead of rebuilding the scene. This complete example modifies the existing `Body` material from the guide example, saves the updated source again and re-exports only the asset hierarchy:

```python
from pathlib import Path
import bpy

out = Path.cwd() / 'art'
body = bpy.data.objects['Body']
material = body.data.materials[0]
material.node_tree.nodes['Principled BSDF'].inputs['Roughness'].default_value = 0.8

# Preserve these edits for the next iteration.
bpy.ops.wm.save_as_mainfile(filepath=str(out / 'source.blend'))
asset = bpy.data.objects['AssetRoot']
bpy.ops.object.select_all(action='DESELECT')
for obj in [asset, *asset.children_recursive]:
    obj.select_set(True)
bpy.ops.export_scene.gltf(filepath=str(out / 'model.glb'), export_format='GLB',
                          use_selection=True, export_yup=True,
                          export_cameras=False, export_lights=False)
```

Run `blender(action="start", blend="art/source.blend", script="art/tweak.py", render="art/preview.png")`, poll until completion and inspect the new preview. The saved camera, lights and render settings are reused. Scripts still follow the existing approval policy. Adapt object names and export selection to your own scene.

Camera and lighting changes affect Blender previews; when those objects are excluded from GLB export, they do not change the imported game's camera or lighting. Make the corresponding game-side changes in Godot and verify the imported result there.

## Export and animation conventions

The guide response includes `example_script`, a complete reusable bpy starting point. It exports only `AssetRoot` and its descendants; preview camera/lights stay in the editable blend but out of the GLB. Keep preview-only backdrop geometry out of the export too. Decide which objects belong to Blender and which effects/lighting remain dynamic in Godot, to avoid duplicates.

Use meters and explicit names. Export `export_yup=True`: Blender coordinates `(x, y, z)` become Godot `(x, z, -y)`. The asymmetric example puts `FrontMarker` on Blender -Y / Godot +Z and `RightMarker` on +X; verify those markers before adding compensating rotations. Your character's desired forward direction is a separate artistic choice. Apply deliberate transforms rather than guessing a 180-degree fix.

Put animated parts under stable named pivot empties, with all moving accessories parented to the same pivot. The example's `Head` is a child of `HeadPivot`, which is under `AssetRoot`. Preserve imported rest transforms when animating. Frame the camera around the subject or a named focus object; whole-scene bounds can be dominated by distant mountains/background geometry. The status report's object world locations and parent names help diagnose hierarchy and placement.

Background scripts should use data APIs and operators that do not need a UI area. A small CPU preview is portable: `scene.render.engine='CYCLES'`, `scene.cycles.device='CPU'`, `scene.cycles.samples=8`, set resolution and `resolution_percentage=100`, configure a camera pointing at the asset and lights. Do not require GPU availability. Blender API names vary by installed version; the report/log identifies the actual version. `--factory-startup`, private user config and disabled automatic scripts avoid depending on the player's open Blender scene/preferences. Deliberately executed bpy scripts can still run arbitrary Python: keep all operations scoped to this game.

## Materials and export feedback

Blender's rendered shader graph is not the glTF material format. Use a Principled BSDF with constant values or recognized image-texture connections. Procedural Noise/ColorRamp and custom shader groups are not automatically preserved as rendered appearance. The [Blender glTF manual](https://docs.blender.org/manual/en/5.2/addons/scene_gltf2.html) describes recognized material connections.

The example's `bake_base_color` helper demonstrates the full route: UV-mapped cube, procedural Noise/ColorRamp color, CPU Cycles diffuse **COLOR-only** bake to an sRGB image, Image Texture directly connected to Principled Base Color, then packed texture exported in GLB. Node color values in this recipe are scene-linear; Blender performs the image encoding. Do not add manual gamma conversion or bake direct/indirect illumination into a relightable base-color texture. Other meshes need UVs, and multi-material meshes need a bake target in each relevant material. This is a base-color recipe, not a universal normal/metallic/roughness baker; those maps need their own channels and color-space settings.

Status includes `warnings` separately from `log_tail`, including on successful runs. Up to 16 distinct warning/error/unsupported/fallback lines are retained (384 characters each); `warnings_dropped` reports omitted occurrences after the limit. Summaries preserve early lines even after render progress pushes them out of the log tail. They are diagnostic hints, not authoritative success/failure classification, and not every exporter silently dropping a feature produces a warning.

`report.material_advisories` independently checks materials used by scene meshes for connected procedural/custom shader nodes. Disconnected experiment nodes and intentionally white materials are not flagged. Inspection is bounded (`material_inspection_limited`), advisory, and neither exhaustive nor proof of which materials were exported: preview-only objects are still in the Blender scene. Follow findings by checking the GLB in Godot. A clean report does not guarantee matching appearance. Lighting, exposure, color management and emission can differ; compare actual images rather than applying a fixed emission-strength cutoff.

Private jobs disable `.blend1` backup creation; they do not delete pre-existing backups or change the player's Blender preferences. Your script still owns render engine, resolution, samples and artistic settings.

## Multiple preview views

One job may write additional workspace PNGs itself. For example, after configuring the example's camera/lights, before saving the blend:

```python
(Path.cwd() / 'art').mkdir(exist_ok=True)
original_location = camera.location.copy()
original_rotation = camera.rotation_euler.copy()
for name, position in [('front', (6, -8, 5)), ('back', (-6, 8, 5))]:
    camera.location = position
    camera.rotation_euler = (Vector((0.5, 0, 1.2)) - camera.location).to_track_quat('-Z', 'Y').to_euler()
    scene.render.filepath = str(Path.cwd() / 'art' / (name + '.png'))
    scene.render.image_settings.file_format = 'PNG'
    bpy.ops.render.render(write_still=True)
camera.location = original_location
camera.rotation_euler = original_rotation
```

Inspect each with `blender(action="inspect", path="art/front.png")` and `art/back.png`. An optional tool-level `render` still produces the main preview after the script returns. Keep all PNGs within inspection limits; multiple views do not replace the imported Godot screenshot.
